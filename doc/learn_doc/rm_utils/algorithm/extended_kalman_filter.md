## 第一部分：数学基础（矩阵知识回顾）

在深入扩展卡尔曼滤波器（EKF）的算法逻辑之前，我们需要先掌握一些底层的矩阵运算知识。这部分内容专为数学基础薄弱的读者设计，我们将抛开晦涩的纯数学证明，用大白话和生活类比来解释这些概念在代码中到底意味着什么，以及为什么它们如此重要。

### 1.1 矩阵转置

**是什么？**

矩阵转置（记作 $A^\top$）就像把矩阵"翻个面"。简单来说，就是把矩阵的"行"变成"列"，把"列"变成"行"。原来在第 1 行的数据，转置后就会跑到第 1 列去。

**为什么重要？**

在 EKF 的公式推导中，转置无处不在。它不仅是数学形式上的要求，更是为了保证矩阵乘法维度匹配、物理意义正确。

**代码中的坑：为什么看不到 H.transpose()？**

很多初学者在看 `extended_kalman_filter.cpp` 时会困惑：课本上的卡尔曼增益公式明明是

$$K = P H^\top S^{-1}$$

为什么代码里计算增益时，完全没看到对观测矩阵 $H$ 做转置操作？

其实，$H$ 的转置被巧妙地"吸收"了。我们来做个简单的推导：

1. 课本公式：$K = P H^\top S^{-1}$
2. 我们对等式两边同时求转置：$K^\top = (P H^\top S^{-1})^\top$
3. 根据矩阵转置的性质 $(AB)^\top = B^\top A^\top$（注意顺序会颠倒！），展开得到：$K^\top = (S^{-1})^\top (H^\top)^\top P^\top$
4. 因为协方差矩阵 $S$ 和 $P$ 都是对称矩阵（即 $S^\top = S$，$P^\top = P$），且转置两次等于本身 $(H^\top)^\top = H$，公式化简为：$K^\top = S^{-1} H P$

**代码的实际操作**：

代码中先利用 `solve` 函数计算了 $S^{-1} H P$，最后再对结果调用一次 `.transpose()` 得到真正的 $K$。这就是为什么你在代码里找不到 `H.transpose()`，因为数学等价变换让它提前被消化了。

### 1.2 矩阵对称

**是什么？**

如果一个矩阵沿着左上到右下的主对角线"镜像折叠"后，两边完全重合，它就是对称矩阵。用数学语言说就是 $A = A^\top$，即 $A_{ij} = A_{ji}$。

**为什么重要？**

在 EKF 中，协方差矩阵（描述不确定性的矩阵）在理论上**必须**是对称的。因为"变量 X 和 Y 的协方差"等于"变量 Y 和 X 的协方差"，即 $\text{Cov}(X,Y) = \text{Cov}(Y,X)$。

**代码中的坑：浮点运算的微小误差**

虽然理论上对称，但在计算机里，由于浮点数运算存在精度损失，经过一连串加减乘除后，原本对称的矩阵可能会出现 `1e-16` 级别的微小不对称。

**强制对称化**：

如果带着这种微小的不对称去进行矩阵分解，底层的数学库（如 Eigen）可能会直接报错崩溃。所以代码中有一行关键操作：

```cpp
S = 0.5 * (S + S.transpose());
```

这就像是把矩阵和它的镜像加起来再除以 2，强行把它"掰"回完美的对称状态，确保后续算法能顺利运行。

---

### 1.3 正定矩阵与特征值

**是什么？**

正定矩阵的一个核心判断标准是：它的**所有特征值都必须严格大于 0**。

**为什么重要？**

协方差矩阵代表的是"不确定性"或"方差"。在物理世界中，方差绝对不可能是负数，所以协方差矩阵必须是正定的。

**代码中的坑：弹簧类比与数值爆炸**

我们可以把特征值想象成弹簧的"弹性系数"：

- **特征值 > 0**：弹簧有弹性，可以被正常压缩和拉伸。
- **特征值 = 0**：弹簧彻底锈死了，卡在一个位置无法动弹（这在数学上叫"奇异矩阵"，不可逆）。

在代码中，我们通过 `innovation_ldlt.vectorD().minCoeff() <= 1e-12` 来检查最小的特征值。如果最小特征值接近或小于 0，说明矩阵"生锈"了。此时如果强行求逆，相当于在公式里除以 0，会导致数值瞬间爆炸，产生无穷大（Inf）或非数字（NaN）。

为了防止整个程序崩溃，代码一旦发现这种情况，会直接拒绝本次更新，安全地回滚到预测状态。

### 1.4 LDLT 分解

**是什么？**

LDLT 分解是把一个对称矩阵 $S$ 拆解成三个矩阵的乘积：

$$S = L D L^\top$$

- $L$ 是下三角矩阵（对角线上的数字全是 1）
- $D$ 是对角矩阵（只有对角线上有数字，其余全是 0）

**为什么重要？**

在 EKF 中，我们需要频繁地解形如 $S X = B$ 的方程组。直接计算 $S$ 的逆矩阵不仅慢，而且容易因为精度问题出错。LDLT 分解就像是把一个大难题拆解成了几个极其简单的小步骤，解方程组时既稳定又高效。

**代码中的体现**：

`Eigen::LDLT<Eigen::MatrixXd> innovation_ldlt(S);` 这一行在创建对象的同时，就在底层完成了复杂的分解工作。

- 通过 `.vectorD()` 可以提取出 $D$ 矩阵的对角元，也就是我们上面提到的"特征值"，用来做安全检查。
- 通过 `.solve(B)` 可以直接解出 $X$，完全不需要显式地去求 $S^{-1}$。

---

### 1.5 Eigen 中 .solve() 的含义

**是什么？**

在 Eigen 库中，`A.solve(B)` 求解的是线性方程组 $S X = B$，也就是求 $X = S^{-1} B$。

**为什么重要？**

矩阵乘法**不满足交换律**，顺序一旦搞反，结果天差地别。

**代码中的坑：千万别记反了**

很多初学者会误以为 `A.solve(B)` 是 $X = B S^{-1}$，这是绝对错误的！

在 EKF 代码中，`innovation_ldlt.solve(H * P_prior)` 实际上是在解 $S X = H P_{\text{prior}}$，算出来的 $X$ 等价于 $S^{-1} H P_{\text{prior}}$。牢记这一点，你在阅读和修改代码时才不会把矩阵乘法的顺序搞乱。

---

### 1.6 allFinite() 与 NaN/Inf

**是什么？**

`allFinite()` 是 Eigen 提供的一个安全检查函数，它会遍历矩阵里的每一个元素，确认它们是不是都是"有限的正常数字"。

**为什么重要？**

在复杂的浮点运算中，如果不小心除以了 0，或者对负数开了平方，就会产生 `NaN`（Not a Number，非数字）或 `Inf`（Infinity，无穷大）。这些"毒数据"一旦混入状态估计，会像病毒一样在后续的每一帧预测和更新中传播，导致整个跟踪系统彻底瘫痪。

**代码中的体现**：

代码在计算出卡尔曼增益、更新状态后，都会严格调用 `allFinite()`。一旦发现任何一个元素变成了 `NaN` 或 `Inf`，程序会立刻拉响警报，拒绝这次更新，保护系统不被污染。

---

### 1.7 点积（内积）

**是什么？**

两个向量的点积（记作 $a^\top b$），就是把它们对应位置的数字相乘，然后再全部加起来：

$$a^\top b = a_0 b_0 + a_1 b_1 + \cdots + a_n b_n$$

**为什么重要？**

在数学本质上，两个列向量的点积等价于 $a^\top b$。它的核心作用是**降维**——把两个包含多个信息的向量，"压缩"成一个单一的标量（一个普通的数字）。

**代码中的体现**：

在 EKF 中，点积常用于计算残差的平方、马哈拉诺比斯距离（判断观测值是否异常）等。它能把多维度的误差信息，汇总成一个可以用来做阈值判断的单一数值。

## 第二部分：扩展卡尔曼滤波（EKF）数学公式详解

### 2.1 卡尔曼滤波的思想概述

卡尔曼滤波的核心思想可以用通俗的语言来理解：

- **状态不可直接获取**：我们关心系统的真实状态（例如目标的位置、速度），但通常无法直接、完整地测量到这些状态。
- **双重信息来源**：我们拥有两个信息来源。一是**模型预测**，即根据物理规律推算出的下一步状态；二是**传感器观测**，即实际测量得到的数值。
- **最优融合**：卡尔曼滤波的作用是"聪明地"将这两个信息融合在一起，得到一个比单一来源更准确的最优估计。
- **预测步骤（Predict）**：利用系统模型推算下一步的状态及其不确定性。
- **更新步骤（Update）**：利用传感器的实际测量数据来修正预测结果，缩小不确定性。

---

### 2.2 状态定义

在本系统中，状态向量定义为：

$$x = [\text{center\_x}, v_x, \text{center\_y}, v_y, \text{center\_z}, v_z, \text{yaw}, \omega, \text{radius\_02}, \text{radius\_13}, h]$$

该状态向量共包含 **11 维**，各维度的物理含义如下：

| 维度 | 含义 |
|------|------|
| center_x | 目标在 x 方向上的中心位置 |
| vx | x 方向上的线速度 |
| center_y | 目标在 y 方向上的中心位置 |
| vy | y 方向上的线速度 |
| center_z | 目标在 z 方向上的中心位置 |
| vz | z 方向上的线速度 |
| yaw | 目标的偏航角（水平面旋转角度） |
| omega | 偏航角速度（绕垂直轴的旋转角速度） |
| radius_02 | 装甲板一条对角线的半径 |
| radius_13 | 装甲板另一条对角线的半径 |
| h | 装甲板的高度 |

### 2.3 预测步骤（Predict）

预测步骤包含两个核心公式，用于在没有新观测的情况下推算系统状态。

#### 2.3.1 状态预测

**公式：**

$$x = f(x)$$

- **变量说明**：$x$ 为状态向量，$f$ 为非线性状态转移函数。
- **物理意义**：根据物理模型，从当前状态推算出下一步的预期状态。
- **代码实现**：在代码中，$f$ 通过 lambda 表达式传入。默认实现为线性形式 $x = F x$，但支持传入自定义的非线性函数以适应复杂的运动学模型。

#### 2.3.2 协方差预测

**公式：**

$$P = F P F^\top + Q$$

- **变量说明**：
  - $P$：状态估计的协方差矩阵，表示状态的不确定性。
  - $F$：状态转移矩阵（即 $f$ 对 $x$ 的雅可比矩阵 Jacobian）。
  - $Q$：过程噪声协方差矩阵，表示模型本身的不确定性或外部干扰。
- **物理意义**：新的不确定性等于旧的不确定性经过系统动力学传播后的结果，再加上模型自身的不确定性。
- **代码实现**：

```cpp
P = F * P * F.transpose() + Q;
x = f(x);
```

### 2.4 更新步骤（Update）

更新步骤是 EKF 的核心，通过融合传感器观测来修正预测状态。

#### 2.4.1 计算残差（Innovation / Residual）

**公式：**

$$e = z - h(x_{\text{prior}})$$

- **变量说明**：$z$ 为传感器实际观测值，$h(x_{\text{prior}})$ 为根据预测状态推算出的预期观测值。
- **物理意义**：残差 $e$ 代表了模型预测与现实观测之间的差距。
- **代码实现**：代码中使用 `z_subtract` 自定义减法函数，以正确处理角度环绕等非线性问题。默认线性实现为 $z - H x$。

#### 2.4.2 计算创新协方差矩阵 S

**公式：**

$$S = H P_{\text{prior}} H^\top + R$$

- **变量说明**：
  - $H$：观测矩阵（雅可比矩阵），描述状态空间到观测空间的映射关系。
  - $R$：观测噪声协方差矩阵，表示传感器自身的测量误差。
- **物理意义**：$S$ 表示预测观测值的总不确定性，包含状态不确定性传播到观测空间的部分（$H P_{\text{prior}} H^\top$）以及传感器自身噪声（$R$）。

#### 2.4.3 对称化 S

**公式：**

$$S = \frac{1}{2}(S + S^\top)$$

- **物理意义**：理论上 $S$ 应为对称矩阵，但由于浮点运算误差可能导致轻微不对称。此步骤强制对称化，保证后续分解的数值稳定性。

#### 2.4.4 LDLT 分解 S

- **操作**：将 $S$ 分解为 $L D L^\top$ 的形式。
- **物理意义**：为后续高效、稳定地求解线性方程组做准备，避免直接求逆带来的数值问题。

#### 2.4.5 计算卡尔曼增益 K

**课本公式：**

$$K = P H^\top S^{-1}$$

- **物理意义**：$K$ 是信任度权重矩阵。$K$ 值越大，表示越相信传感器观测；$K$ 值越小，表示越相信模型预测。
- **代码实现**：

```cpp
K = innovation_ldlt.solve(H * P_prior).transpose();
```

- **推导说明**：利用对称性，$K^\top = (P H^\top S^{-1})^\top = S^{-1} H P$。代码中 `solve` 直接解出 $S^{-1} H P$，再转置得到 $K$，避免了显式计算 $H^\top$ 和 $S^{-1}$。

#### 2.4.6 计算 NIS（归一化创新平方）

**公式：**

$$\text{NIS} = e^\top S^{-1} e$$

- **物理意义**：NIS 衡量了残差相对于预期不确定性的"异常程度"。若 NIS 过大，说明观测与预测严重不符，可能存在传感器故障或模型失效（详见第三部分）。
- **代码实现**：

```cpp
innovation_solution = S^-1 * residual; // 通过 solve 实现
nis = residual.dot(innovation_solution);
```

#### 2.4.7 状态更新

**公式：**

$$x = x_{\text{prior}} + K e$$

- **物理意义**：用加权后的残差修正预测状态。
- **代码实现**：

```cpp
x = x_add(x_prior, K * residual);
```

- **特殊处理**：由于状态中包含 `yaw` 角度，普通加法会导致角度溢出（如 359° + 2° ≠ 361°）。`x_add` 函数专门处理角度环绕问题，确保角度值始终在合法范围内。

#### 2.4.8 协方差更新（Joseph 形式）

**公式：**

$$P = (I - KH) P_{\text{prior}} (I - KH)^\top + K R K^\top$$

- **物理意义**：更新状态估计的不确定性。Joseph 形式相比标准形式 $P = (I - KH) P_{\text{prior}}$，额外增加了 $K R K^\top$ 项，能有效防止浮点误差导致 $P$ 失去对称正定性，数值稳定性更好。
- **代码实现**：更新后再次进行对称化处理：

```cpp
P = 0.5 * (P + P.transpose());
```

## 第三部分：NIS 与 NEES 详解

### 3.1 NIS（Normalized Innovation Squared，归一化创新平方）

**核心公式：**

$$\text{NIS} = e^\top S^{-1} e$$

**通俗解释：**

- **residual（残差）$e$**：代表"预测与现实的差距"，是一个向量。
- **S（创新协方差）**：代表这个差距的"不确定性"，是一个矩阵。
- **NIS**：将差距"标准化"（除以不确定性），最终得到一个单一的数值。
- **生活类比**：假设你预测明天温度为 20°C，实际为 22°C，偏差为 2°C。如果你的预测模型本身方差很大（本来就不准），2°C 的偏差很正常；但如果你的模型方差极小（预测极准），2°C 的偏差就非常可疑。NIS 就是用来量化这种"可疑程度"的指标。

**NIS 的统计性质：**

- 若滤波器工作正常（模型正确且噪声参数合理），NIS 服从卡方分布（$\chi^2$ 分布）。
- 自由度 = 有效观测维度（即 $H$ 矩阵中非零行的数量）。
- 代码中的 `nisThreshold` 函数根据自由度返回 95% 置信水平的阈值：

| 自由度 | 95% 卡方阈值 |
|--------|-------------|
| 1 维 | 3.841 |
| 2 维 | 5.991 |
| 3 维 | 7.815 |
| 4 维 | 9.488 |
| 5 维 | 11.070 |
| 6 维 | 12.592 |
| 7 维 | 14.067 |
| 8 维 | 15.507 |

**代码实现细节：**

```cpp
// 1. 用 LDLT 分解求解 S^-1 * residual
const Eigen::VectorXd innovation_solution = innovation_ldlt.solve(residual);
// 2. 点乘得到标量 NIS
const double nis = residual.dot(innovation_solution);
```

- **为何不用 `S.inverse() * residual`？** 直接求逆不仅计算速度慢，而且在数值上极不稳定。
- `residual.dot(innovation_solution)` 在数学上完全等价于 $e^\top S^{-1} e$，且计算效率更高。

**NIS 超过阈值意味着什么：**

- 观测值"太离谱"，与预测值的差距超出了合理范围。
- **可能原因**：传感器发生故障、出现异常值（野值）、或系统模型不匹配。
- **代码处理策略**：拒绝本次更新，回滚到先验状态，并记录更新失败。

**activeObservationDimension 函数说明：**

- 该函数用于计算 $H$ 矩阵的有效观测维度（即非零行数）。
- 在实际系统中，某些观测行可能会被屏蔽（例如副板 yaw 观测），因此并非所有行都有效。
- 判定标准：使用 `H.row(row).squaredNorm() > 1e-18` 来判断某一行是否"非零"。

---

### 3.2 NEES（Normalized Estimation Error Squared，归一化估计误差平方）

**核心公式：**

$$\text{NEES} = (x - x_{\text{prior}})^\top P^{-1} (x - x_{\text{prior}})$$

**通俗解释：**

- **$x - x_{\text{prior}}$**：代表"状态更新量"，即根据观测值对状态进行了多大的调整。
- **$P$**：代表更新后的协方差，反映了对新状态的信任程度。
- **NEES**：用于衡量状态调整的量是否在合理的统计学范围内。
- **生活类比**：假设预测位置在 10m，传感器测得在 12m，于是调整了 2m。如果协方差 $P$ 很小（你对自己极度自信），调整 2m 就很可疑；如果 $P$ 很大（你对自己不太确定），调整 2m 则非常合理。

**代码实现细节：**

```cpp
const Eigen::VectorXd state_delta = x - x_prior;
const Eigen::VectorXd state_solution = posterior_ldlt.solve(state_delta);
nees = state_delta.dot(state_solution);
```

- 此处使用的是**后验协方差 $P$**（更新后的），而不是先验 $P_{\text{prior}}$。
- **阈值设定**：固定为 19.68（对应 11 维状态空间下 95% 的卡方分布阈值）。

**NEES 超过阈值意味着什么：**

- 状态更新量过大，滤波器可能正在发散。
- **可能原因**：即使 NIS 检查通过，但更新量依然过大，这通常说明底层模型存在根本性问题。

---

### 3.3 NIS 和 NEES 的关系

- **NIS** 负责检查"观测值本身是否合理"。
- **NEES** 负责检查"状态的更新幅度是否合理"。
- **互补关系**：
  - 若 NIS 通过但 NEES 不通过：说明观测值看起来正常，但导致的更新量过大（模型可能存在隐患）。
  - 若两者均不通过：说明滤波器出现了严重问题。

## 第四部分：数值安全检查机制

本部分详细解释代码中的"防御性编程"设计，这是保障工程稳定性的核心环节。

### 4.1 S 矩阵检查（第一道关卡）

```cpp
if (innovation_ldlt.info() != Eigen::Success ||
    !innovation_ldlt.vectorD().allFinite() ||
    innovation_ldlt.vectorD().minCoeff() <= 1e-12 ||
    !residual.allFinite())
    return reject_numeric_update();
```

只要以下四个条件中有任何一个失败，即拒绝更新：

1. **LDLT 分解失败**（说明 $S$ 矩阵不是正定的）。
2. **$D$ 的对角元包含 NaN 或 Inf**。
3. **最小特征值 $\le 10^{-12}$**（矩阵接近奇异，数值极度不稳定）。
4. **残差向量包含 NaN 或 Inf**。

### 4.2 K 矩阵检查（第二道关卡）

```cpp
if (!K.allFinite())
    return reject_numeric_update();
```

- 在计算出卡尔曼增益 $K$ 后，立即进行有限性检查。

### 4.3 NIS 检查（第三道关卡）

```cpp
if (!innovation_solution.allFinite() || !std::isfinite(nis) || nis < 0.0)
    return reject_numeric_update();
```

- **nis < 0.0 检查的意义**：数学上 $S$ 是正定矩阵，二次型 $e^\top S^{-1} e$ 的结果必须 $\ge 0$。如果计算出负数，说明浮点误差已经严重到不可接受的程度。

### 4.4 后验检查

```cpp
if (!x.allFinite() || !P.allFinite() || P.diagonal().minCoeff() < -1e-12)
    return reject_numeric_update();
```

- 更新后的状态 $x$ 和协方差 $P$ 必须全部为有限值。
- $P$ 的对角元（代表方差）绝对不能为负数。

### 4.5 后验协方差正定性检查

```cpp
const Eigen::LDLT<Eigen::MatrixXd> posterior_ldlt(P);
if (posterior_ldlt.info() != Eigen::Success ||
    !posterior_ldlt.vectorD().allFinite() ||
    posterior_ldlt.vectorD().minCoeff() < -1e-9)
    return reject_numeric_update();
```

- 对更新后的 $P$ 再次进行 LDLT 分解检查。
- 阈值放宽至 $-10^{-9}$：因为 Joseph 形式在理论上能保证正定性，但浮点运算可能会产生极小的负值。

### 4.6 reject_numeric_update 回滚机制

```cpp
const auto reject_numeric_update = [&]() -> Eigen::VectorXd {
    x = x_prior;           // 回滚状态
    P = P_prior;           // 回滚协方差
    data["nis_fail"] = 1.0; // 标记失败
    data["nis"] = 0.0;     // 清零 NIS
    // ... 其他清理工作
    return x;              // 返回安全的先验状态
};
```

- 这是系统的"紧急刹车"：任何一项检查失败，都会立即回滚到更新前的状态。
- 保证滤波器不会因为一次坏数据或数值异常而彻底发散。
- **类比**：就像做数学题算到一半发现数字不对，立刻划掉重写，退回到上一个已知正确的步骤。

## 第五部分：代码与公式逐行对照

下表将关键代码片段与对应的数学公式进行了逐行对照：

| 步骤 | 数学公式 | 代码实现 |
|------|----------|----------|
| 状态预测 | $x = f(x)$ | `x = f(x)` |
| 协方差预测 | $P = F P F^\top + Q$ | `P = F * P * F.transpose() + Q` |
| 残差计算 | $e = z - h(x)$ | `residual = z_subtract(z, h(x))` |
| 创新协方差 | $S = H P_{\text{prior}} H^\top + R$ | `S = H * P * H.transpose() + R` |
| 对称化处理 | $S = \frac{1}{2}(S + S^\top)$ | `S = 0.5 * (S + S.transpose())` |
| LDLT 分解 | $S = L D L^\top$ | `Eigen::LDLT<Eigen::MatrixXd> ldlt(S)` |
| 卡尔曼增益 | $K = P H^\top S^{-1}$ | `K = solve(H * P).transpose()` |
| NIS 计算 | $e^\top S^{-1} e$ | `residual.dot(solve(residual))` |
| 状态更新 | $x = x_{\text{prior}} + K e$ | `x = x_add(x, K * residual)` |
| 协方差更新 (Joseph) | $P = (I-KH)P_{\text{prior}}(I-KH)^\top + K R K^\top$ | `P = (I-K*H)*P*(I-K*H).transpose() + K*R*K.transpose()` |
